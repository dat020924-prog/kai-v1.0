# 2026-11-15

## Backend vnstock Timeout Fix (v1.9)

### Problem
- `/api/vn30f1m` and `/api/vn30f1m/realtime` endpoints were crashing/hanging when vnstock.io.vn API timed out
- `requests.get` was blocking Uvicorn worker threads with no overall timeout protection
- Earlier test: direct Python `requests.get` to vnstock timed out after 15s

### Fix Applied
- Added `ThreadPoolExecutor` with `max_workers=2` to isolate vnstock calls from main thread
- `_fetch_vn30f1m_from_vnstock_threaded()` wraps calls with `future.result(timeout=10s)`
- Shortened HTTP timeout from 15s → 8s (`_VNSTOCK_REQ_TIMEOUT`)
- Added `threading.Lock()` for cache access thread-safety
- Cache: 5-min TTL, thread-safe read/write
- Fallback chain preserved: vnstock → robotstock → mock

### Verification
- All endpoints responding: `/api/vn30f1m` (1D, 5m), `/api/vn30f1m/realtime` ✅
- Data source: vnstock (real data, not simulated for 1D)
- Simulated intraday bars working correctly for non-1D resolutions
